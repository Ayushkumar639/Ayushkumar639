## 🧠 About

I'm an Electronics & Communication Engineering student (Avionics) building at the intersection of **AI/ML, full-stack software, and embedded avionics systems**. My work ranges from a BiLSTM + Attention GPS-spoofing detector for UAV navigation, to a self-hosted CPU-only 3D-generation engine, to production-style full-stack platforms — each one shipped, documented, and demoed end-to-end rather than left as a notebook experiment.

I'm based in Jammu, India, working from inside a 3-member academic research team and a 2-month space-systems research internship at IIST. What interests me most is taking research-grade ideas — sequence models, signal processing, sensor fusion — and turning them into systems that are testable, reasonably secure, and actually run on real hardware constraints (CPU-only, no external IMU, non-NVIDIA GPUs).

## 🚀 Featured Projects

<details>
<summary><b>🛰️ AI/ML-Based GPS Spoofing Detection for UAV Navigation</b></summary>
<br/>

Academic research project built with a 3-person team, designed around a software-only constraint — no external IMU hardware. The system flags two classes of GPS spoofing (meaconing and active) on unencrypted L1 C/A signals in real time.

| Stack | Scale | Performance | Security | Impact | Repository |
|---|---|---|---|---|---|
| Python, BiLSTM, Attention, 1D-CNN, HMAC-SHA256, Matplotlib, Chart.js | 3-person team · 13-scene dashboard · 4 flight paths | 2 spoofing types detected on unencrypted L1 C/A signals | HMAC-SHA256-secured STRC Checkpoint Session System, tiered real-time alert state machine | IEEE-formatted research paper + 8-slide technical presentation | [View on GitHub →](https://github.com/Ayushkumar639?tab=repositories) |

The 3-stage BAC pipeline (BiLSTM + Attention + 1D-CNN) feeds into **STRC**, the team's original HMAC-SHA256-secured checkpoint session system, which drives a tiered real-time alert state machine. Statistical validation ran through a live attack-emulation pipeline, producing 8 Matplotlib figures that back the team's IEEE-formatted paper. The results are visualized in a 13-scene HTML/Chart.js command-center dashboard — 4 flight paths, satellite PRN skyplots, live alerts, anomaly-score detection, and CSV export.

</details>

<details>
<summary><b>🧊 Forge3D — Self-Hosted AI 3D Model Generation Tool</b></summary>
<br/>

A $0-cost, CPU-only 3D-generation engine built as an offline, self-hosted alternative to Meshy.ai — designed to run on hardware without an NVIDIA GPU.

| Stack | Scale | Performance | Security | Impact | Repository |
|---|---|---|---|---|---|
| Flask, Three.js, TripoSR, Python | $0-cost, fully local, CPU-only pipeline | Runs on non-NVIDIA hardware (AMD GPU, 16GB RAM) | Server-side pixel watermarking — flags canvas-generated images | Unlocked non-NVIDIA hardware support for local 3D generation | [View on GitHub →](https://github.com/Ayushkumar639?tab=repositories) |

The core engineering challenge was CUDA dependence: `torchmcubes` only runs on NVIDIA hardware, so it was replaced with a custom `torchmcubes_shim.py` built on scikit-image's marching cubes implementation, unlocking CPU-only and AMD-GPU machines. A pixel-watermarking approach — a reserved `(0,0) = RGB(1,2,3)` marker — lets the server detect canvas-generated output.

</details>
